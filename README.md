# Бот заявок в чат квартала

Человек подаёт заявку → бот спрашивает в личке, живёт ли человек в квартале и в каком доме (или в каком квартале) → в админ-чат приходит карточка с кнопками «Принять / Отклонить».
Если человек не ответил за 48 ч, заявка отклоняется автоматически. Все решения записываются в журнал (`decisions`).

## Права бота
В общем чате боту нужно **только** право «Добавление участников» (приглашения). Остальные права не давать.
В админ-чате бот — обычный участник (или админ без прав), чтобы писать туда карточки.

## Что видно в карточке
Ответы на вопросы, фото профиля, username, Premium, примерный год создания аккаунта (по id),
язык Telegram, личный канал, по какой ссылке пришёл, bio и — если настроено — в каких чатах домов состоит.

Совет: создавайте **именованные** ссылки-приглашения («Объявление в лифте», «От соседей дома 5»),
тогда в карточке будет видно, откуда пришёл человек.

### Проверка по чатам домов
1. Добавить бота в чаты домов обычным участником (права админа не нужны).
2. Написать `/chatid` в каждом чате.
3. Вписать id через запятую в `HOUSE_CHAT_IDS` в `wrangler.toml`.

## Локальный тест

1. В @BotFather создать **тестового** бота, взять токен.
2. `cp .dev.vars.example .dev.vars` и вписать токен и любую случайную строку в `WEBHOOK_SECRET` (`openssl rand -hex 32`).
3. Создать две группы: «Тест чат» (в настройках включить «Одобрять новых участников») и «Тест админы».
4. Добавить бота в обе группы, в «Тест чат» — админом с правом приглашать.
5. Узнать id групп:
   - `npm run dev` в одном терминале, `npm run poll` во втором;
   - написать `/chatid` в каждой группе;
   - вписать id в `wrangler.toml` (`MAIN_CHAT_ID`, `ADMIN_CHAT_ID`), перезапустить `npm run dev`.
6. `npm run db:local` — создать локальную базу (один раз).
7. Со второго аккаунта открыть ссылку-приглашение тестового чата и подать заявку.

Проверить автоотклонение: временно поставить `EXPIRE_HOURS = "0"` и открыть
`http://localhost:8787/__scheduled` — это запуск планировщика вручную.

## Боевой запуск (Cloudflare)

```sh
npx wrangler login
npx wrangler d1 create join-bot          # вписать database_id в wrangler.toml
npm run db:remote
npx wrangler secret put BOT_TOKEN
npx wrangler secret put WEBHOOK_SECRET
npm run deploy                           # выдаст адрес https://join-request-bot.<...>.workers.dev
npm run webhook -- https://join-request-bot.<...>.workers.dev
```

После `npm run webhook` локальный `npm run poll` с этим же токеном использовать нельзя: он снимает вебхук.
Поэтому для тестов держите отдельного бота.

## Проверка работоспособности
- `https://join-request-bot.msk-pb-8-district.workers.dev/health`: 200 и `"ok":true`, если всё хорошо, и 503, если есть проблема.
  Этот адрес можно подключить к UptimeRobot или похожему сервису, тогда при падении придёт письмо.
- Раз в час бот проверяет себя сам и пишет в `ADMIN_CHAT_ID`, если база недоступна или Telegram не может доставить события.
- `/status` в личке с ботом (только для админов общего чата) показывает состояние и статистику заявок.
- Логи в реальном времени: `npx wrangler tail`.
